# AGENTS.md

## Назначение

`AGENTS.md` задаёт правила работы агента с репозиторием `Collaby`. Это не обзор архитектуры, а документ поведения: в каком порядке читать контекст, где искать источник истины и как поддерживать документацию в пригодном для агента виде.

## Что здесь является источником истины

- Этот файл — источник истины для правил работы агента и правил ведения repo-owned Markdown.
- Корневой [README.md](README.md) — источник истины для фактов о репозитории: карта каталогов, runtime-контракт, CI/CD-контракт и список связанных документов.
- Локальные `README.md` в подкаталогах — источник истины только для своей области, если они не противоречат корневому `README.md`.

## Что агент должен знать перед изменениями

- Начинайте чтение контекста с корневого `README.md`, затем переходите к ближайшему локальному `README.md` в затронутом каталоге, и только потом к коду и конфигам.
- Не используйте Markdown как обзорный или маркетинговый текст. Каждый tracked `.md` в репозитории должен быть рабочим артефактом для агента.
- Если меняется runtime, CI/CD, структура каталогов, границы bounded context или deploy-процедура, агент обязан обновить соответствующий `README.md` в том же change set.
- Если локальный документ повторяет глобальные факты из корневого `README.md`, локальный документ должен ссылаться на root README, а не переписывать его целиком.
- `services/` предназначен только для функциональных runtime-сервисов. Исключения — нейтральный `platform/` как source of truth для общих runtime-примитивов, internal contracts и repo-owned event schemas, а также `services/ManagementService/ManagementService.Tests/` как management-owned test layer для общих test helper’ов и repo-level guardrail-тестов.

## Правила для repo-owned Markdown

Все tracked `.md`, принадлежащие репозиторию, считаются агентскими артефактами и должны помогать агенту быстро восстановить нужный контекст при ограниченном окне.

### Обязательная роль документов

- `README.md` в корне — фактический индекс репозитория.
- `AGENTS.md` в корне — правила поведения агента и правила ведения документации.
- Остальные tracked `README.md` — локальные инструкции по своей подсистеме, сервису или инфраструктурному каталогу.

### Обязательная смысловая структура

Для новых repo-owned `.md` используйте такой порядок разделов, если он применим:

1. `Назначение`
2. `Что здесь является источником истины`
3. `Что агент должен знать перед изменениями`
4. `Локальные команды/проверки`
5. `Связанные документы`

Допускается опускать раздел `Локальные команды/проверки`, если для области нет собственных воспроизводимых локальных проверок.

### Требования к содержанию

- Пишите коротко и фактологично.
- Явно указывайте границы области: чем каталог владеет, а чем нет.
- Ссылайтесь на реальные source-of-truth файлы: compose, Dockerfile, скрипты, конфиги, solution, project files.
- Фиксируйте инварианты и контракты, которые агенту нельзя не заметить перед изменением.
- Не дублируйте большие фрагменты root README в leaf-документах.

### Что запрещено

- Делать tracked `.md` личными заметками, аудит-логом или произвольным narrative-текстом.
- Оставлять в tracked `.md` секреты, временные пароли, access notes и одноразовые результаты ручной проверки.
- Превращать `AGENTS.md` в дубликат архитектурного README или `README.md` в дубликат правил для агента.

## Исключения из этого контракта

Эти Markdown-файлы не считаются repo-owned агентскими артефактами и не обязаны следовать шаблону:

- ignored/local-файлы вроде `server-connect.md`
- локальные credential notes вроде `panels/panel-credentials.local.md`
- временные артефакты и отчёты в `qa-artifacts/**`
- будущие generated Markdown-документы, если они будут явно производиться инструментами

## Язык документации и комментариев

- Новые repo-owned `README.md` и другие tracked `.md` пишутся на русском языке.
- Новые ручные комментарии в коде и скриптах также пишутся на русском языке.
- Машинно-значимые токены не переводятся: пути, команды, env vars, route segments, имена сервисов, image refs, JSON keys и аналогичные литералы.
